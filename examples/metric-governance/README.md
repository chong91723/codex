# 通用指标口径演示（虚构数据）

本目录是独立验收夹具，不连接任何客户数据库，也不代表推荐的会计准则。`seed.sql` 仅由测试运行器在它自己创建、使用后删除的 PostgreSQL 容器中执行。产品查询账号 `reader` 只有只读权限。业务表名、字段和公式在示例配置中；通用执行引擎不内置电商业务常量。

## 示例一：电商订单贡献利润

虚构业务问题：按订单归属日期，统计已完成订单的净收款、净履约成本、贡献利润和贡献利润率，并说明退款与取消订单的处理。

这个演示显式采用以下**待业务人员确认**的口径：

- 日期采用数据库中的 `booked_on`，起始日期包含、结束日期不包含；它不是收入确认日期或退款发生日期。
- 只统计 `status = completed`；取消订单全部排除。
- 净收款 = 收款金额 − 已退款金额；净履约成本 = 履约成本 − 已回收成本。
- 贡献利润 = 净收款 − 净履约成本；贡献利润率 = 贡献利润 ÷ 净收款 × 百分比换算系数。
- 退款和成本回收归属原订单日期，不处理跨期冲销、税额、汇率、支付手续费或仓储费用。
- 金额以虚构的统一记账单位表达，字段无 NULL。生产数据中的 NULL 不能默认套用该假设。
- 金额采用十进制计算；展示的小数位、舍入方式和分母为零时的行为由规则明确规定。零分母返回空值，不能假装利润率为零。
- 样例中全部假设仅用于演示。保存草稿不会自动把它升级为经客户认可的生产口径；需要在界面中显式确认。

边界数据：一笔部分退款、一笔全额退款、一笔应排除的取消订单、恰好位于区间右边界的订单、全额退款导致的零分母月份，以及收入等于成本导致的零利润月份。

## 示例二：服务处理效率

使用独立表 `demo_service_cases`，只统计已关闭服务请求。计算耗时总分钟数、请求数、平均耗时、满足单位总数、请求单位总数和满足率。该模板使用相同规则和执行入口，证明能力不绑定电商或利润公式。满足率按总满足单位除以总请求单位计算，不能用各行比率的简单平均代替。

## 文件与验证边界

- `seed.sql`：独立测试数据库和只读账号。
- `ecommerce-rule.json`、`service-rule.json`：可分别在数据源的“指标口径 → 新增口径草稿 → 导入 JSON 文件”中导入的配置。导入后仍需保存草稿并显式确认。`rule.json` 是测试运行器使用的合集，不能直接作为单条配置导入。数据源 ID 由界面或测试绑定。
- `expected.json`：人工设计用例后由 `generate_examples.py` 使用独立 Decimal 计算生成的参考结果；该脚本不导入产品指标引擎，不作为产品执行的返回值。运行 `python3 examples/metric-governance/generate_examples.py` 可重建配置与参考结果。
- `web/tests/run_metric_demo.py`：启动和清理自有数据库、测试环境，并运行真实 MCP 与浏览器检查。
- `web/tests/metric_demo_desktop.mjs`：规则管理、确认、真实执行、版本隔离、停用和证据展示/导出的桌面回归。

自动验收中，查询和指标计算是真实执行。用来展示已有发布结果的聊天事件是明确标记的 UI 夹具，不等同于真实模型对话。缺少有效测试环境密钥时不发起 DeepSeek 请求，不宣称 Agent 能力或模型端到端耗时已验证。
